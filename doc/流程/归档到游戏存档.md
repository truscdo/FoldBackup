# 归档到游戏存档流程

本文定义把归档库中的完整归档或“完整归档 + 差分归档”恢复为 Minecraft 游戏存档目录的流程。

## 1. 输入与产物

| 项 | 内容 |
| --- | --- |
| 输入 | 归档库中的完整归档 `S-x[full].tar`，以及可选的差分归档 `S-base[S-target].tar` |
| 产物 | 目标目录下的游戏存档：世界元数据、区域文件、实体区域、数据文件等 |
| 归档库 | 只读：不写入、不移动、不删除归档 |
| 目标目录 | 不存在时自动创建（含缺失的父目录）；存在时如果能识别为游戏存档，就地更新 |
| 临时空间 | 差分恢复在系统临时目录暂存 LRHD 替换区块；写入落盘使用目标同目录临时文件 |

归档恢复只读取归档目录，不依赖在线仓库。Region 与普通文件的内容身份与快照、备份共用同一套定义。

执行顺序固定为：基线 → 计划 → 目标检查与锁 → 检查阶段 → 统计与决策 → 写入 → 删除。统计必须在决策之前产出，用户先看到会删除什么，再决定是否删除。

入口与[快照到游戏存档](快照到游戏存档.md)一致：CLI 为 `foldbackup archive export`，TUI 为归档库 → 导出为游戏存档。选项与互斥见[CLI 命令设计方案](../CLI命令设计方案.md)，菜单步骤、提示与默认路径见[TUI 设计方案](../TUI设计方案.md)。

## 2. 基线

差分归档不能独立恢复。恢复差分归档时，归档库中必须存在其 `baseEpoch` 对应的完整归档；缺失时报错，不用在线仓库的数据替代。

```text
确定基线
├─ 输入是完整归档: 基线就是自身，没有差分
└─ 输入是差分归档
   ├─ 读出 baseEpoch
   ├─ 在归档库中找该 epoch 的完整归档
   └─ 缺失: 报错，列出期望的归档文件名
```

目标的最终状态由差分归档的清单决定，基线只提供未变化的内容。

## 3. 计划

写入之前先完整建立计划，任何校验失败都不会产生写入。

```text
建立恢复计划
├─ 读取完整归档与差分归档的 snapshot.bin
├─ 断言 diff.baseEpoch 与 full.epoch 一致
├─ 合并目标清单
│  ├─ 内容身份在基线中出现过: 由基线提供
│  ├─ 新增或变化: 由差分归档提供
│  └─ 文件对象: 基线没有时从差分的 objects/files/ 取
├─ 校验路径唯一、区域坐标唯一、文件与目录不冲突
└─ 任一不一致: 报错，不写入
```

## 4. 目标检查与锁

与[快照到游戏存档](快照到游戏存档.md)一致：输出路径为空白或没有文件/目录名时报错；目标不存在时自动创建（含缺失的父目录），创建只发生在写入阶段；目标存在时必须是目录，非空时必须包含 `level.dat`，空目录视为新建且不取锁；游戏存档识别之后取得世界锁，并持有到写入与删除结束。检查阶段不改动目标清单与用户文件（除了锁文件 `session.lock`），只检查不执行的预检不创建目录。

## 5. 检查阶段

判定与[快照到游戏存档](快照到游戏存档.md)的检查阶段相同：复用[在线备份设计方案](../在线备份设计方案.md)第 2、3 节定义的元数据比较与内容身份计算，与备份的差异同样适用，只把比较对象换成目标归档的清单。差别只在内容来源：普通文件与区域从 tar 读取，区域需要合并基线 LRH 与差分 LRHD。

目标目录的遍历是恢复独有的，用来得到删除候选：

```text
检查目标目录
├─ 不在目标清单中的普通文件: 删除候选(需要排除session.lock)
├─ 不在目标清单中的 .mca: 区域单元删除候选
└─ .mcc 只随区域单元处理
```

## 6. 统计

| 组 | 内容 |
| --- | --- |
| 更改 | 待写入的区域与文件数量 |
| 跳过 | 元数据命中的区域与文件、内容身份命中的区域与文件 |
| 删除 | 总数、按后缀分组的数量（无扩展名单列）、会被完全删除的目录 |

统计在检查阶段结束后就绪，删除阶段的总数同样取自此处的计数，在删除开始前已经确定。删除组始终产出；未选择连带删除时它只表示目标中将被保留的条目。

只检查不执行的预览输出与执行相同的数字且不写入、不删除，但仍然取得世界锁，保证与随后的执行看到同一个世界状态。统计先于决策产出；决策在 CLI 由参数预先表达、在 TUI 由菜单选择，见[CLI 命令设计方案](../CLI命令设计方案.md)与[TUI 设计方案](../TUI设计方案.md)。

进度分为检查、恢复文件、恢复区域、删除四个阶段；恢复阶段的总数只含实际需要处理的条目。

## 7. 写入

```text
写入每个待写入条目
├─ 普通文件
│  ├─ 从完整或差分 tar 取对象，解压到同目录临时文件
│  ├─ 边写边计算内容身份，与记录比较
│  ├─ 一致: 改名覆盖
│  └─ 不一致: 删除临时文件并报错
└─ 区域
   ├─ 解码基线 LRH 帧
   ├─ 按顺序消费并校验 LRHD 帧，替换变化区块
   ├─ 重建 .mca（zlib），超过 255 扇区的区块写入 .mcc
   ├─ 内容身份一致: 原子改名落地
   ├─ 删除本次写入未生成的 .mcc
   └─ 不一致: 删除临时文件并报错
```

写入完成后把修改时间设为源元数据中与条目同路径文件的源时间；区域取 `.mca` 的记录，本次生成的 `.mcc` 沿用同一时间；取不到记录时保留写入时间。被跳过的条目不读取、不移动、不重写，修改时间保持原样。

帧的解压由写入驱动：目录内只有存在待写入区域时才打开该帧；帧一旦打开就从帧首顺序消费到帧尾，以完成该帧的完整性校验，途中被跳过的区域数据会被顺带解压，但不产出。目录内没有待写入区域时不打开帧，整个写入集合为空时不消费任何帧。基线中未变化、差分包里没有帧的区域本来就没有帧需要读。归档整体的完整性由 `archive verify` 负责；回档只校验它实际消费到的帧与区块。

region 文件按整体替换，该单元内本次未重新生成的 `.mcc` 随写入清除，与是否开启连带删除无关。写入逐条落地，中途失败不回滚已落地的条目，目标可能处于部分更新状态。

## 8. 删除

删除只在显式选择连带删除时执行，排在全部写入与校验之后。

差分归档里记录的删除项——`files.bin` 的删除记录，以及基线有而目标清单没有的路径——本来就满足“不在目标清单中”，并入统一删除规则，不再单独处理。未开启连带删除时，目标中不在目标清单里的内容全部保留。区域单元在写入时已被整体替换，其内未重新生成的 `.mcc` 不在此列。删除完成后，统计中列为会被完全删除的目录一并移除；此时仍有其他文件留下的目录保持原样。
