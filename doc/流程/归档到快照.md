# 归档到快照流程

本文定义把归档 tar 导入在线仓库、生成在线快照的流程。

## 1. 输入与产物

| 项 | 内容 |
| --- | --- |
| 输入 | 归档根目录下的归档 tar：完整归档 `S-x[full].tar`，差分归档 `S-base[S-target].tar` |
| 产物 | 在线仓库 `index.db` 中的快照记录与 `blobs/` 中的内容 blob |
| 归档 tar | 只读 |
| 临时空间 | 合并差分时在系统临时目录暂存当前 Region 的替换数据，逐 Region 释放 |

`导入`与`在线备份`的区别只在内容来源：在线备份扫描世界目录，导入读取归档 tar；两者写出的 manifest 与 blob 身份规则相同。

## 2. 归档 tar 结构

```text
归档 tar
├─ snapshot.bin
│  └─ 目标快照的完整路径清单：Region 与普通文件的路径、内容身份、大小、源元数据
├─ objects/regions/<contentHash>.lrh
├─ objects/files/<sourceHash>.zst
├─ files.bin                      (仅差分归档)
│  └─ 基线 epoch，以及普通文件的新增、修改、删除
└─ <维度目录>/diff.lrhd           (仅差分归档)
   └─ 变更区块的替换数据
```

## 3. 基线

导入的基线只有一种来源：该 epoch 的在线快照。

```text
解析基线
├─ 按差分归档的 baseEpoch 加载在线快照
│  ├─ 存在: 作为内容来源
│  └─ 缺失: 报错，列出期望的快照 ID 与对应完整归档名
└─ 不打开完整归档
```

前提是完整归档先被导入。完整归档导入时对象已按内容哈希落入 `blobs/`，基线内容因此在线可用。

批量导入按 epoch 升序处理，天然满足“完整归档先导入”。单个完整归档导入失败时，依赖它的差分归档报基线缺失。

## 4. 批量流程

```text
归档导入
├─ 扫描归档根，一次建立内存索引
│  ├─ 读取每个 tar 的 snapshot.bin
│  ├─ snapshot.bin 缺失或不可读: 记为错误，跳过该 tar
│  └─ 记录文件名、类型与 epoch
├─ 按 epoch 升序排序
├─ 同 epoch 多份完整归档
│  ├─ 内容一致: 按文件名排序保留第一份，输出警告
│  └─ 内容不同: 记为错误，列出该 epoch 的全部文件，该 epoch 不导入
├─ 逐个导入
│  ├─ 完整归档: 执行第 5 节
│  ├─ 差分归档: 执行第 6 节
│  └─ 单个归档失败: 记录错误后继续
└─ 汇总
   ├─ 有错误: 聚合后抛出，已导入的快照保留
   └─ 无错误: 返回导入数量
```

## 5. 完整快照导入

```text
导入完整归档
├─ 打开归档 tar，读取 snapshot.bin
├─ 判重
│  ├─ 同 epoch 快照已存在且内容一致: 跳过，不读取任何对象
│  └─ 已存在但内容不同: 冲突报错，不覆盖
├─ Region 对象
│  ├─ blob 已存在: 复用，不读取对象
│  └─ 不存在: 边读边校验 contentHash，写入 blobs
├─ 普通文件对象
│  ├─ blob 已存在: 复用，不读取对象
│  └─ 不存在: 边解压边校验 sourceHash 与大小，写入 blobs
└─ 提交
   ├─ 由 snapshot.bin 生成 manifest
   └─ 写入索引
```

判重比较的是目标清单与已有快照的元数据：快照身份、epoch、世界与版本信息，以及每个 Region 与每个文件的内容哈希、解压后大小、源元数据。不比较 tags，也不比较压缩后大小与 blob 路径。

## 6. 差分快照导入

```text
导入差分归档
├─ 读取 snapshot.bin 与 files.bin
├─ 判重（按 epoch 查在线快照）
│  ├─ 已存在且内容一致: 跳过
│  └─ 已存在但内容不同: 冲突报错，不覆盖
├─ 解析基线（见第 3 节）
├─ 校验 files.bin.baseEpoch 与基线 epoch 一致
├─ Region
│  ├─ 目标 contentHash 的 blob 已存在: 复用
│  └─ 缺失: 基线 Region 帧与 diff.lrhd 合并
│     ├─ 写入 blobs
│     └─ 校验合并结果的 contentHash
├─ 普通文件
│  ├─ blob 已存在: 复用，不读取对象
│  └─ 不存在: 从差分归档或基线复制，校验 sourceHash 与大小
└─ 提交（同第 5 节）
```

未变化的 Region 与文件在基线中已存在对应 blob，因此不进入合并或复制，也不重新读取。被删除的路径不出现在目标清单中，随 manifest 一起丢失引用。

## 7. 校验

| 对象 | 校验内容 | 时机 |
| --- | --- | --- |
| 归档条目 | 路径合法、无重复、不越出 tar 边界 | 建立索引时 |
| Region 对象 | 解压后按网格顺序重算 `contentHash` | 写入 blob 时 |
| 合并后的 Region | 合并结果重算 `contentHash` 并与目标一致 | 写入 blob 时 |
| 普通文件对象 | 解压后重算 `sourceHash` 与大小 | 写入 blob 时 |
| `diff.lrhd` | 结构、Region 坐标、区块哈希 | 读取时 |
| 在线复用的 blob | 不重复解压，信任内容寻址 | — |
| `snapshot.bin`、`files.bin` | 可解码，`baseEpoch` 与基线一致 | 读取时 |

导入不做“写入前全量预检”。需要预检时使用 `archive verify`。

## 8. 错误处理

| 情况 | 行为 |
| --- | --- |
| 基线快照不存在 | 报错，列出期望的快照 ID 与对应完整归档名，提示先导入该完整归档 |
| 同 epoch 多份完整归档，内容一致 | 保留第一份，输出警告 |
| 同 epoch 多份完整归档，内容不同 | 保留第一份，报错，列出文件 |
| 目标 Region 或文件无法解析 | 报错，给出路径、哈希与来源（差分归档或基线） |
| 同 epoch 快照已存在且内容不同 | 冲突报错，不覆盖 |
| 单个归档失败 | 记录并继续，最后聚合抛出；已导入的快照保留 |
| 导入中断 | 已提交的快照保留；未被引用的 blob 由后续 GC 回收 |
