# 构建与测试指南

本指南面向第一次构建或运行测试的开发者。命令均从项目根目录的 **Git Bash** 执行，并使用项目自带的 Gradle Wrapper。

## 快速查询

| 目标 | 命令 | 会运行什么 |
| --- | --- | --- |
| 只生成可发布的模组 JAR | `./gradlew jar` | 编译主代码并打包，不运行测试 |
| 同时生成无启动脚本变体 | `./gradlew jar -PjarNoScripts` | 额外产出 `foldbackup-<version>-noscripts.jar` |
| 只生成无启动脚本变体 | `./gradlew jarNoScripts` | 只打包 `foldbackup-<version>-noscripts.jar` |
| 构建项目产物，不运行测试 | `./gradlew assemble` | 编译并打包，不运行 `check` 或测试 |
| 常规构建和单元测试 | `./gradlew build` | 构建产物并运行 `check`，其中包含单元测试；不会运行 `integrationTest` |
| 运行全部单元测试 | `./gradlew test` | 运行 `src/test` 中的 JUnit 5 测试 |
| 运行一个单元测试类 | `./gradlew test --tests 'io.github.truscdo.foldbackup.cli.BootstrapSupportTest'` | 只运行指定测试类 |
| 运行服务器集成测试 | `./gradlew integrationTest` | 准备并启动 NeoForge 测试服务器，再运行 `src/integrationTest` 测试 |
| 运行一个集成测试类 | `./gradlew integrationTest --tests '*OverworldBackupAndRollbackIT'` | 只运行指定集成测试类 |
| 清理构建输出 | `./gradlew clean` | 删除 `build/` 下的构建产物 |

**一般开发建议**：只需要拿到 JAR 时运行 `jar`；修改代码后做快速验证时运行 `test`；提交或发布前运行 `build`。只有需要验证真实 NeoForge 服务器行为时才运行 `integrationTest`。

## 首次准备

- 安装并使用 **JDK 21**。
- 在 Git Bash 中进入项目根目录。
- 使用以下命令配置项目内的 Gradle 缓存和测试临时目录：

```bash
mkdir -p .gradle/.tmp
PROJECT_DIR_WIN="$(cygpath -m "$PWD")"
export GRADLE_USER_HOME="$PROJECT_DIR_WIN/.gradle"
export JAVA_TOOL_OPTIONS="-Djava.io.tmpdir=$GRADLE_USER_HOME/.tmp"
```

环境变量只对当前 Git Bash 窗口生效。重新打开窗口后再次执行。`JAVA_TOOL_OPTIONS` 让 Gradle、测试 JVM 及测试启动的 Java 子进程将默认临时文件写到项目的 `.gradle/.tmp`。

项目通过 `./gradlew` 固定使用 Gradle Wrapper 8.10；无需单独安装或调用系统 Gradle。

## 构建说明

### 快速打包

```bash
./gradlew jar
```

主 JAR 输出到 `build/libs/`，当前文件名为 `foldbackup-0.1.0.jar`。此 JAR 同时用于 NeoForge 模组和命令行工具。

### 无启动脚本变体（noscripts）

标准产物会在备份根目录释放 TUI 启动脚本。`noscripts` 变体用于不需要该副作用的发布场景，除下列内容外与标准 JAR 完全一致：

| 被移除的内容 | 说明 |
| --- | --- |
| `scripts/tui-launcher.bat.tmpl`、`scripts/tui-launcher.sh.tmpl` | 启动脚本模板 |
| `core/ScriptWriter.class` | 模板渲染实现，移除后无任何调用方 |
| 真实的 `core/StartupScriptInstaller.class` | 由 `src/noLauncherScripts` 中同签名的空实现替换 |

运行时差异只有一处：该变体不会在备份根目录生成 `foldbackup-tui.bat` / `foldbackup-tui.sh`，其余功能完全相同。单元测试始终针对标准实现运行。

两种构建方式：

```bash
./gradlew jar -PjarNoScripts   # 标准 JAR + 变体，共享编译只需一次
./gradlew jarNoScripts         # 只产出变体
```

### 不运行测试，只准备构建产物

```bash
./gradlew assemble
```

`assemble` 负责编译和打包，不经过 `check`，适合只想确认产物能否生成的场景。

### 常规构建

```bash
./gradlew build
```

`build` 会执行 `check`，其中包括常规单元测试。当前构建配置没有把 `integrationTest` 挂到 `check` 上，因此 `build` 不会启动集成测试服务器。

## 测试说明

### 单元测试

运行全部单元测试：

```bash
./gradlew test
```

只运行指定类：

```bash
./gradlew test --tests 'io.github.truscdo.foldbackup.core.store.SnapshotStoreTest'
```

测试源文件位于 `src/test/java/`，使用 JUnit 5。标准 HTML 报告位于 `build/reports/tests/test/index.html`，XML 报告位于 `build/test-results/test/`。

### NeoForge 服务器集成测试

运行全部集成测试：

```bash
./gradlew integrationTest
```

只运行指定类：

```bash
./gradlew integrationTest --tests '*EntityRollbackIT'
```

集成测试位于 `src/integrationTest/java/`，通过独立 NeoForge 服务端进程和 RCON 验证端到端行为。Gradle 会先准备服务器运行文件、编译代码并生成 JAR，再由测试启动服务器。

运行前请确认本机 **25575 端口空闲**，并且没有其他进程占用测试世界。测试运行目录为 `build/integrationTest/run/`；每个集成测试类运行前都会重建该目录。服务器日志和测试报告分别写入：

- `build/reports/integrationTest/`
- `build/reports/integrationTest/artifacts/<测试类名>/`
- `build/test-results/integrationTest/`

常见集成测试类：

| 测试类 | 覆盖内容 |
| --- | --- |
| `OverworldBackupAndRollbackIT` | 主世界备份与回滚流程 |
| `MultiDimensionRollbackIT` | 多维度回滚流程 |
| `EntityRollbackIT` | 实体回滚流程 |
| `BootstrapTuiChainIT` | 发布 JAR 的 Bootstrap、依赖提取和 TUI 启动链路 |

## 常见选择

- **只想快速生成 JAR**：运行 `./gradlew jar`。
- **不想运行任何测试**：运行 `./gradlew assemble`，不要用 `build`。
- **想验证本地代码且不启动游戏服务器**：运行 `./gradlew test`。
- **想做提交前常规构建**：运行 `./gradlew build`；它运行单元测试，但跳过服务器集成测试。
- **需要检查游戏内服务器行为或发布 JAR 启动链路**：单独运行 `./gradlew integrationTest`，可用 `--tests` 缩小范围。

如果 Gradle 报告缺少 Java 工具链，先检查当前 JDK 是否为 21；如果集成测试无法启动，先检查 25575 端口和 `build/integrationTest/run/` 中是否有被占用的世界锁文件。
