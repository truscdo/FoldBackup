# FoldBackup

[English](../../README.md) | [简体中文](README.zh.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-br.md) | Русский

FoldBackup — это инструмент резервного копирования миров для серверов Minecraft на NeoForge. Он поддерживает автоматическое и ручное создание резервных снимков (snapshots), сжатие в архивы, предварительный просмотр исторических чанков и откат отдельных чанков.

Снимки используют схему дедупликации данных, похожую на Git: каждая резервная копия записывает только новые и изменённые файлы. Файлы регионов хранятся в формате LRH. На сервере выживания Minecraft 1.21.1 NeoForge с более чем 80 модами архив, созданный на уровне сжатия 19, может занимать всего треть от исходного размера мира.

Один и тот же JAR-файл можно установить как мод NeoForge или запускать как самостоятельный инструмент. Он предоставляет интерфейс командной строки (CLI) и интерактивное меню (TUI), что позволяет работать с резервными копиями, когда сервер выключен.

- **Окружение**: Minecraft `1.21.1`, NeoForge `21.1+`, Java `21+` (функции автономного режима CLI / TUI не привязаны к версии игры и совместимы с большинством версий Minecraft)
- **Установка**: Требуется только на **сервере** (или в клиенте для одиночной игры); игрокам, подключающимся к серверу, **не** нужно устанавливать этот мод на свои клиенты, чтобы пользоваться всеми функциями (включая внутриигровой предварительный просмотр исторических чанков)

## Возможности

- **Резервное копирование онлайн**: Планируйте создание копий по суммарному времени присутствия игроков на сервере, запускайте их вручную или настройте автоматическое копирование при запуске и остановке сервера.
- **Автономное резервное копирование**: Создавайте резервные копии миров через TUI или CLI без запуска игры.
- **Дедупликация данных**: Неизменённые данные не занимают дополнительного места в новом снимке.
- **Управление снимками**: Просматривайте сводку по занятому месту репозитория и уникальный, общий и суммарно освобождаемый объём каждого снимка, закрепляйте важные снимки (`pin`) для защиты от автоматической очистки, оценивайте освобождаемое место перед пакетным удалением и настраивайте автоматическую очистку.
- **Предварительный просмотр и откат чанков**: Просматривайте исторический вид чанка в игре и восстанавливайте отдельный чанк из выбранного снимка в мир; также можно откатывать чанки в сохранении через CLI без запуска игры, чтобы устранять проблемные чанки или сбои из-за слишком большого количества сущностей.
- **Быстрый полный откат**: При экспорте снимка в виде мира Minecraft, если в указанном месте уже существует сохранение игры, неизменённые части пропускаются для ускорения отката.
- **Сжатие в архивы**: Создавайте полные или дифференциальные архивы с высокой степенью сжатия для распространения или хранения; их можно восстановить как мир Minecraft или импортировать в репозиторий снимков. Для серверов дифференциальные архивы позволяют передавать только изменённые части сохранения для локального редактирования карты.

> [!NOTE]
> **Разница между снимками (Snapshots) и архивами (Archives)**:
>
> - **Снимки**: Частые автоматические или ручные резервные копии, хранящиеся с инкрементной дедупликацией в локальном репозитории; используются для быстрого отката, экспорта мира и восстановления отдельных чанков.
> - **Архивы**: Отдельные файлы, оптимизированные для высокой степени сжатия (поддерживаются полные и дифференциальные архивы); подходят для внешнего холодного хранения, синхронизации между машинами или распространения миров.

### LRH и Linear

**LRH — это потоковая реализация на основе формата регионов Linear**, используемая в FoldBackup для сжатия и хранения данных регионов. Исходный проект — [xymb-endcrystalme/LinearRegionFileFormatTools](https://github.com/xymb-endcrystalme/LinearRegionFileFormatTools). Благодарим его авторов за разработку формата и реализацию.

В FoldBackup также представлен формат LRHD для записи различий между чанками в архивах, что обеспечивает дифференциальное резервное копирование и хранение на уровне чанков.

## Быстрый старт

### Создание резервной копии

1. Поместите JAR-файл FoldBackup в каталог `mods/` сервера NeoForge.
2. Запустите сервер и дождитесь загрузки мира и инициализации FoldBackup.
3. В игре выполните следующие команды с уровнем прав 2 или выше:

   ```text
   /foldbackup backup --force
   /foldbackup list
   ```

   В одиночной игре владелец мира может использовать эти команды даже при выключенных читах. Другие игроки, подключившиеся по локальной сети (LAN), использовать их не могут.

По умолчанию резервные копии сохраняются в каталоге `foldbackups/` внутри рабочего каталога сервера; путь можно изменить через `general.backupPath`. Выделенный сервер использует этот каталог непосредственно как репозиторий, а в одиночной игре используется `foldbackups/<имя-папки-мира>`, чтобы у каждого мира был собственный репозиторий.

Автоматическое резервное копирование по умолчанию включено. Интервал отсчитывает накопленное время, пока на сервере есть игроки. На ручное резервное копирование также распространяется минимальный интервал между копиями; используйте `/foldbackup backup --force`, чтобы обойти это ограничение.

Даже без установки мода в игру можно автономно создавать снимки сохранений Minecraft любой версии с помощью CLI или TUI:

<details>
<summary>Нажмите, чтобы развернуть инструкции по автономному созданию резервных копий через CLI / TUI</summary>

> Перед запуском TUI или CLI необходимо сначала распаковать встроенные в JAR библиотеки времени выполнения (это позволяет избежать конфликтов зависимостей между модом и CLI), а затем запускать TUI или CLI (если используется скрипт быстрого запуска TUI, этот шаг можно пропустить).
>
> ```bash
> # Выделенный сервер: foldbackups/
> java -jar ../mods/foldbackup-<version>.jar extract
>
> # Одиночная игра: foldbackups/<имя-папки-мира>
> java -jar ../../mods/foldbackup-<version>.jar extract
> ```
>
> По умолчанию команды считают текущий каталог каталогом репозитория целевого мира (`foldbackups/` на выделенном сервере, `foldbackups/<имя-папки-мира>` в одиночной игре). Если вы запускаете их из другого места, скорректируйте соответствующие параметры.

**Перед автономным резервным копированием обязательно остановите сервер или выйдите из мира одиночной игры.**

**Создание снимка через CLI:**

```bash
# Создать снимок с правилами фильтрации по умолчанию
java -jar ../mods/foldbackup-<version>.jar snapshot create --world ../world

# Добавить дополнительные правила исключения (заключайте шаблоны с * или ** в кавычки, чтобы оболочка не раскрывала их заранее)
java -jar ../mods/foldbackup-<version>.jar snapshot create --world ../world \
  --exclude "**/DistantHorizons.sqlite" \
  --exclude "cache/"
```

- `--world <каталог>`: Обязательный; указывает на корневой каталог сохранения мира.
- `--exclude <glob>`: Необязательный, можно указывать несколько раз; добавляет исключения поверх правил фильтрации по умолчанию.

**Создание снимка через TUI:**

Запустите `java -jar ../mods/foldbackup-<version>.jar tui` (или скрипт запуска) в каталоге репозитория, выберите пункт **`6. Create snapshot from world`** и последовательно введите:

1. **Каталог мира**: Укажите путь к корневому каталогу сохранения мира (Enter — вернуться в главное меню).
2. **Дополнительные правила исключения**: Сначала экран покажет базовые защитные правила; при необходимости добавьте несколько правил через запятую в одной строке (поддерживается `{a,b}`, например `**/DistantHorizons.sqlite, cache/`). Нажмите Enter, чтобы ничего не добавлять, или `0`, чтобы вернуться назад; при неверном синтаксисе правила программа попросит повторить ввод.
3. **Количество потоков**: Введите положительное целое число, нажмите Enter для автоматического выбора или введите `0`, чтобы вернуться назад.

**Правила фильтрации файлов:**

- При автономном создании снимков всегда сохраняются 4 базовых правила по умолчанию: `**/session.lock`, `**/backups`, `**/.backups` и `**/*.wip` (в отличие от стандартной конфигурации мода, автономный режим по умолчанию не исключает `**/DistantHorizons.sqlite` — при необходимости добавьте его вручную, как показано выше).
- Правила сопоставляются с путями относительно каталога мира, используют `/` в качестве разделителя и **не могут начинаться с `/`** (например, пишите `backups/`, а не `/backups/`); поддерживаются `*`, `**`, `?`, `[...]` и `{a,b}`.
- При совпадении каталога пропускается всё его поддерево; правило, заканчивающееся на `/` (например, `cache/`), сопоставляется только с каталогами и не затрагивает одноимённые файлы. Пустые правила, ведущий `/` или некорректный синтаксис glob немедленно завершают выполнение с ошибкой.

</details>

### Быстрый запуск TUI

Если вам удобнее запускать меню скриптом, сохраните один из приведённых ниже скриптов в каталог репозитория под именем `foldbackup-tui.bat` или `foldbackup-tui.sh` (в Linux выполните для него `chmod +x`). Скрипт ищет JAR-файл рядом с собой, затем в `../mods`, а затем в `../../mods`, и автоматически распаковывает встроенные библиотеки времени выполнения.

<details>
<summary>Нажмите, чтобы развернуть скрипт запуска для Windows (<code>foldbackup-tui.bat</code>)</summary>

```bat
@echo off
setlocal DisableDelayedExpansion
set "SCRIPT_DIR=%~dp0"
set "JAR="
call :find "%SCRIPT_DIR%."
call :find "%SCRIPT_DIR%..\mods"
call :find "%SCRIPT_DIR%..\..\mods"
if not defined JAR (
    echo Error: foldbackup jar not found beside this script, in ..\mods, or in ..\..\mods.
    pause
    exit /b 1
)
java -jar "%JAR%" extract --output "%SCRIPT_DIR%.foldbackup-cli"
if errorlevel 1 (
    echo Error: failed to export bundled libraries ^(read-only repository directory?^).
    pause
    exit /b 1
)
java -jar "%JAR%" tui --snapshot-root "%SCRIPT_DIR%." --archive-root "%SCRIPT_DIR%." --lib "%SCRIPT_DIR%.foldbackup-cli"
set "RESULT=%ERRORLEVEL%"
if not "%RESULT%"=="0" pause
exit /b %RESULT%

:find
if defined JAR exit /b 0
if exist "%~1\foldbackup.jar" set "JAR=%~1\foldbackup.jar"
if defined JAR exit /b 0
for %%f in ("%~1\foldbackup-*.jar") do if not defined JAR if exist "%%~ff" set "JAR=%%~ff"
exit /b 0
```

</details>

<details>
<summary>Нажмите, чтобы развернуть скрипт запуска для Linux / macOS (<code>foldbackup-tui.sh</code>)</summary>

```sh
#!/bin/sh
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
JAR=
for dir in "$SCRIPT_DIR" "$SCRIPT_DIR/../mods" "$SCRIPT_DIR/../../mods"; do
    if [ -f "$dir/foldbackup.jar" ]; then
        JAR="$dir/foldbackup.jar"
        break
    fi
    for candidate in "$dir"/foldbackup-*.jar; do
        if [ -f "$candidate" ]; then
            JAR="$candidate"
            break
        fi
    done
    if [ -n "$JAR" ]; then
        break
    fi
done
if [ -z "$JAR" ]; then
    echo "Error: foldbackup jar not found beside this script, in ../mods, or in ../../mods." >&2
    exit 1
fi
java -jar "$JAR" extract --output "$SCRIPT_DIR/.foldbackup-cli" || {
    echo "Error: failed to export bundled libraries (read-only repository directory?)." >&2
    exit 1
}
exec java -jar "$JAR" tui --snapshot-root "$SCRIPT_DIR" --archive-root "$SCRIPT_DIR" --lib "$SCRIPT_DIR/.foldbackup-cli"
```

</details>

### Откат чанка

Вы можете предварительно просмотреть и откатить отдельный чанк прямо в игре либо использовать CLI для отката чанка непосредственно в файлах отключённого мира.

В игре используйте `/foldbackup preview from <snapshot-id>` (по умолчанию используется чанк, в котором вы стоите) или `/foldbackup preview from <snapshot-id> at <x> <z>`, чтобы просмотреть чанк из снимка. Эта команда изменяет отображение целевого чанка на клиенте, показывая его состояние на момент создания снимка, но не изменяет сам чанк на сервере. `x` и `z` — координаты чанка; их можно посмотреть на экране F3 или получить делением координат блока на 16 с округлением вниз. Просматриваемый чанк выделяется синими частицами. Используйте `/foldbackup preview exit`, чтобы завершить просмотр.

Для отката чанка в игре используйте `/foldbackup rollback chunk from <snapshot-id>`, чтобы откатить чанк, в котором вы сейчас находитесь. Чтобы указать конкретные координаты, добавьте `at <x> <z>` или `in <измерение> at <x> <z>` (обязательно при запуске из консоли сервера или RCON), а при необходимости сузьте область через `blocks` (только рельеф, блочные сущности и POI с сохранением текущих сущностей) или `entities` (только сущности, без изменения блоков и блочных сущностей): например, `/foldbackup rollback chunk blocks from <snapshot-id> at <x> <z>` или `/foldbackup rollback chunk entities from <snapshot-id> in <измерение> at <x> <z>`. Целевой чанк должен быть загружен в память. Для незагруженного чанка воспользуйтесь автономным методом через CLI, описанным ниже:

<details>
<summary>Нажмите, чтобы развернуть инструкции по автономному откату через CLI</summary>

> Перед запуском TUI или CLI необходимо сначала распаковать встроенные в JAR библиотеки времени выполнения (это позволяет избежать конфликтов зависимостей между модом и CLI), а затем запускать TUI или CLI (если используется скрипт быстрого запуска TUI, этот шаг можно пропустить).
>
> ```bash
> # Выделенный сервер: foldbackups/
> java -jar ../mods/foldbackup-<version>.jar extract
>
> # Одиночная игра: foldbackups/<имя-папки-мира>
> java -jar ../../mods/foldbackup-<version>.jar extract
> ```
>
> По умолчанию команды считают текущий каталог каталогом репозитория целевого мира (`foldbackups/` на выделенном сервере, `foldbackups/<имя-папки-мира>` в одиночной игре). Если вы запускаете их из другого места, скорректируйте соответствующие параметры.

**Остановите сервер перед выполнением автономного отката.**

Просмотр списка снимков:

```bash
java -jar ../mods/foldbackup-<version>.jar snapshot list
```

Скопируйте ID нужного снимка из списка и выполните откат чанка. Следующая команда восстанавливает чанк `[x, z]` в каталоге Верхнего мира `world` до состояния из указанного снимка:

```bash
java -jar ../mods/foldbackup-<version>.jar snapshot rollback <snapshot-id> --world ../world --chunk <chunk-x> <chunk-z> [--scope <all|blocks|entities>]
```

`--world` указывает на каталог целевого измерения: используйте корень мира для Верхнего мира (Overworld), `../world/DIM-1` для Незера, `../world/DIM1` для Энда или соответствующий каталог `dimensions/<пространство_имён>/<путь>` для пользовательского измерения. `--chunk` принимает знаковые целые координаты чанка, а не координаты блоков. Параметр `--scope` по умолчанию равен `all`, либо может принимать значения `blocks` (только рельеф, блочные сущности и POI) или `entities` (только сущности). Перед выполнением CLI запрашивает подтверждение; добавьте `--yes`, чтобы пропустить запрос.

По умолчанию CLI восстанавливает рельеф целевого чанка, блочные сущности, восстанавливаемые данные сущностей и точки интереса (POI) этого чанка в точности так, как они были записаны в снимке, включая состояние занятости билетов (tickets). Данные игроков и настройки уровня всего мира не затрагиваются.

</details>

### Полное восстановление мира

Из-за соображений производительности полный откат мира прямо в игре пока не поддерживается, но вы можете откатить всё сохранение через TUI или CLI.

> Перед запуском TUI или CLI необходимо сначала распаковать встроенные в JAR библиотеки времени выполнения (это позволяет избежать конфликтов зависимостей между модом и CLI), а затем запускать TUI или CLI (если используется скрипт быстрого запуска TUI, этот шаг можно пропустить).
>
> ```bash
> # Выделенный сервер: foldbackups/
> java -jar ../mods/foldbackup-<version>.jar extract
>
> # Одиночная игра: foldbackups/<имя-папки-мира>
> java -jar ../../mods/foldbackup-<version>.jar extract
> ```
>
> По умолчанию команды считают текущий каталог каталогом репозитория целевого мира (`foldbackups/` на выделенном сервере, `foldbackups/<имя-папки-мира>` в одиночной игре). Если вы запускаете их из другого места, скорректируйте соответствующие параметры.

```bash
# Выделенный сервер: foldbackups/
java -jar ../mods/foldbackup-<version>.jar tui

# Одиночная игра: foldbackups/<имя-папки-мира>
java -jar ../../mods/foldbackup-<version>.jar tui
```

В меню выберите «2. Export world files» и следуйте подсказкам, чтобы выбрать снимок, формат экспорта (каталог или ZIP) и путь вывода. Нажмите Enter, чтобы принять путь по умолчанию (`world-export/<snapshot-id>` или то же имя с расширением `.zip` для ZIP-архива).

> [!IMPORTANT]
> **Сначала остановите сервер**, прежде чем экспортировать данные в каталог активного мира для его восстановления.

При экспорте в каталог целью может быть существующее сохранение игры: FoldBackup обновляет только те файлы, которые отличаются от снимка, и пропускает идентичные файлы. Перед экспортом выполняется проверка; после проверки выберите «1 = overwrite», чтобы оставить в целевом каталоге файлы, которых нет в снимке, или «2 = delete extra», чтобы удалить их и привести целевой каталог в полное соответствие со снимком. На запрос количества потоков можно нажать Enter для использования значения по умолчанию.

Тот же экспорт можно выполнить через CLI: `snapshot export <snapshot-id> --output <каталог>`. Флаг `--zip` создаёт ZIP-архив; при экспорте в каталог `--delete-extra` удаляет файлы, отсутствующие в снимке; `--dry-run` выводит статистику без записи и удаления файлов.

### Полные и дифференциальные архивы

Архивы предназначены для хранения и распространения миров с приоритетом на высокую степень сжатия. Поскольку создание архивов требует значительных ресурсов, операции с ними доступны только через CLI и TUI.

Архивы создаются из снимков, поэтому перед созданием архива необходим снимок. Его можно создать в игре либо через TUI или CLI. В TUI выберите «5. Create archive», затем выберите снимок и тип архива; для дифференциального архива требуется выбрать более ранний снимок для сравнения, чтобы сохранить только изменения.

Архив можно восстановить как мир Minecraft («7. Restore as world files» в TUI) или импортировать как снимок в репозиторий снимков. При восстановлении в виде мира, если в целевом месте уже есть сохранение игры, обновление также выполняется на его основе, а выбор «delete extra» удаляет файлы, которых нет в архиве. При распространении мира с помощью архивов можно упаковать вместе мод и скрипт запуска TUI (текст скрипта приведён выше).

Формат архива не зависит от версии Minecraft. Вы можете использовать CLI или TUI для сжатия миров тех версий игры, которые сам мод не поддерживает.

## Основные внутриигровые команды

| Команда | Назначение |
| --- | --- |
| `/foldbackup backup` | Создать снимок вручную |
| `/foldbackup backup --force` | Создать резервную копию без ожидания минимального интервала |
| `/foldbackup list [страница]` | Показать список снимков (по 10 на странице) со сводкой по месту в репозитории (уникальное, общее и освобождаемое) |
| `/foldbackup status` | Показать состояние задач |
| `/foldbackup info <snapshot-id>` | Показать подробную информацию о снимке и распределение уникального/общего места |
| `/foldbackup delete [--dry-run] <id1> [id2 ...]` | Удалить один или несколько снимков или оценить освобождаемое место с `--dry-run` |
| `/foldbackup pin <snapshot-id>` | Закрепить снимок, защитив его от автоочистки и ручного удаления |
| `/foldbackup unpin <snapshot-id>` | Снять закрепление со снимка |
| `/foldbackup preview from <snapshot-id> [at <x> <z>]` | Предварительный просмотр исторического чанка в текущем измерении (по умолчанию — текущий чанк) |
| `/foldbackup preview exit` | Завершить предварительный просмотр |
| `/foldbackup rollback chunk from <snapshot-id> [at <x> <z>]` | Откатить один чанк в текущем измерении (по умолчанию — текущий чанк) |
| `/foldbackup rollback chunk from <snapshot-id> in <измерение> at <x> <z>` | Откатить один чанк в указанном измерении |
| `/foldbackup rollback chunk blocks from <snapshot-id> [in <измерение> at <x> <z> \| at <x> <z>]` | Откатить только блоки, блочные сущности и POI чанка (с сохранением текущих сущностей) |
| `/foldbackup rollback chunk entities from <snapshot-id> [in <измерение> at <x> <z> \| at <x> <z>]` | Откатить только сущности чанка (не затрагивая блоки и блочные сущности) |

## Ключевые параметры конфигурации

Файл конфигурации по умолчанию находится по пути `config/foldbackup-server.toml` в рабочем каталоге. Имена в таблице указаны в формате `группа.ключ`.

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `general.enabled` | `true` | Включить автоматическое резервное копирование |
| `general.backupPath` | `./foldbackups` | Корневой каталог резервных копий относительно рабочего каталога сервера; также поддерживаются абсолютные пути. Выделенный сервер использует его как репозиторий; в одиночной игре внутри него создаётся отдельный репозиторий для каждой папки мира |
| `general.compressionLevel` | `6` | Уровень сжатия Zstd, от 1 до 22 |
| `scheduling.intervalMinutes` | `30` | Накопленное время присутствия игроков онлайн между автоматическими копиями, в минутах |
| `scheduling.minIntervalMinutes` | `10` | Минимальное реальное время между резервными копиями, в минутах |
| `scheduling.savePauseStallSeconds` | `300` | Прервать копирование и восстановить автосохранение мира, если сканирование мира не продвигается указанное время (в секундах); 0 отключает проверку |
| `scheduling.backupOnStart` | `false` | Создавать резервную копию при запуске |
| `scheduling.backupOnStop` | `false` | Создавать резервную копию при остановке |
| `retention.enabled` | `true` | Включить автоматическую очистку |
| `retention.maxSizeGB` | `50` | Целевой размер репозитория после очистки, в ГиБ; 0 — без ограничений |
| `retention.minFreeSpaceGB` | `5` | Целевое свободное место в файловой системе, в ГиБ; 0 отключает это ограничение |
| `retention.maxAgeDays` | `0` | Максимальный срок хранения снимков, в днях; 0 — без ограничений |
| `performance.regionThreads` | `0` | Количество рабочих потоков; 0 — автоматический выбор |
| `performance.regionMemoryLimitMB` | `0` | Лимит памяти для потоковых задач; 0 — автоматический выбор |
| `logging.progressLogIntervalSeconds` | `3` | Интервал в секундах между сообщениями о прогрессе в журнале (1 — наиболее подробно, 300 — наиболее кратко) |
| `localization.defaultLanguage` | `en_us` | Язык, используемый при отключённом определении языка игрока или если язык клиента не поддерживается; одно из значений: `zh_cn`, `en_us`, `es_es`, `pt_br`, `ru_ru` |
| `localization.autoDetectPlayerLanguage` | `true` | Использовать язык клиента каждого игрока, если он поддерживается |

> [!WARNING]
> **Автоматическая очистка может удалить все незакреплённые снимки.** Ограничения по умолчанию контролируют только размер репозитория (50 ГиБ) и свободное место (5 ГиБ), поэтому для достижения этих целей автоматическая очистка может удалять и недавние снимки.
>
> Закрепляйте важные снимки командой `/foldbackup pin <snapshot-id>` (или через CLI/TUI), установите все три ограничения очистки в 0, чтобы отключить автоматическое удаление, или выключите автоматическую очистку параметром `retention.enabled`.

Параметр `general.excludePatterns` сопоставляет пути относительно каталога мира, используя `/` в качестве разделителя пути и без ведущего `/`. По умолчанию исключаются `**/session.lock`, `**/backups`, `**/.backups`, `**/*.wip` и `**/DistantHorizons.sqlite`. Если под шаблон подпадает каталог, исключается всё его поддерево, а завершающий символ `/` (например, `backups/`) сопоставляется только с каталогами. Параметры фильтрации при автономном создании снимков через CLI / TUI см. в разделе «Создание резервной копии» выше.
