# 离线回档设计方案

本文定义把快照或归档恢复为 Minecraft 游戏存档目录的统一架构，也就是离线回档。两种输入的流程细节分别见[快照到游戏存档](流程/快照到游戏存档.md)与[归档到游戏存档](流程/归档到游戏存档.md)，本文只说明两者共用的流程骨架与设计取舍。

## 1. 统一流程

```text
离线回档
├─ 解析输入
│  ├─ 快照 ID 非法或不存在: 报错
│  └─ 归档文件不存在或不是归档: 报错
├─ 建立目标状态
│  ├─ 快照: 读取快照记录
│  └─ 归档: 完整归档与差分归档合并为恢复计划
│     └─ 差分基线缺失: 报错
├─ 目标检查与锁
│  ├─ 参数非法（空白或没有文件目录名）: 报错
│  ├─ 不是目录或非空且缺 level.dat: 报错
│  ├─ 空目录或不存在的目录: 视为新建，不取锁
│  └─ 识别为游戏存档: 取得世界锁，持有到删除结束
├─ 检查
│  └─ 逐条目比较，得到写入集合、跳过集合与删除候选
├─ 统计
├─ 决策
│  ├─ 仅覆盖
│  ├─ 连带删除
│  └─ 取消
├─ 写入
└─ 删除
```

两种输入只有三处不同，其余步骤共用同一份实现：

| 项 | 快照到游戏存档 | 归档到游戏存档 |
| --- | --- | --- |
| 目标状态 | 快照记录 | 完整归档与差分归档合并后的计划 |
| 内容来源 | 在线仓库的 blob | tar 条目与基线 LRH 的合并结果 |
| 删除候选 | 目标目录遍历的差异 | 目标目录遍历的差异加差分删除记录 |

共用的是目标检查与世界锁、逐条目比较、统计、写入校验与落地、删除执行；不共用的是目标状态的构建方式与内容来源。决策在 CLI 由参数预先表达、在 TUI 由菜单步骤表达，选项与菜单细节见[CLI 命令设计方案](CLI命令设计方案.md)与[TUI 设计方案](TUI设计方案.md)。

## 2. 业务设计

### 2.1 默认覆盖

回档的目标是让目标目录回到清单描述的状态，因此默认语义是覆盖：目标目录不存在时创建（含缺失的父目录），已存在时就地更新，清单中的条目覆盖目标中的同名条目。

覆盖不等于整份重写。检查阶段先比较源元数据与内容身份，未变化的条目直接跳过，不读取、不重写。这样做是为了加快速度：重复回档同一份输入时，实际写入量取决于两者的差异，而不是世界的体积。

### 2.2 默认不删除多余条目

快照与归档只记录备份范围内的内容，不记录过滤配置；被过滤规则排除的路径在快照里没有任何记录。如果按“清单之外即删除”处理，回档就会把过滤掉的目录一并清除，例如遥远的地平线（Distant Horizons）的缓存。

因此默认保留目标中不在清单里的内容，只有显式选择连带删除时才移除(除了世界锁文件)。

### 2.3 Region 按单元处理

普通文件一个路径就是一个条目，Region 不是：一个 `.mca` 与它 32×32 区块范围内的 `.mcc` 共同构成一个区域单元，`.mcc` 承载超过扇区上限的区块。二者分开处理会出现 `.mca` 已替换而 `.mcc` 仍是旧的（或反过来）的错位状态，因此把它们视为一体：

- 比较时以region单元为单位，`.mcc` 不单独判断是否变化；
- 写入时region单元整体替换，本次未重新生成的 `.mcc` 随写入清除，不受连带删除影响；
- 删除时 `.mcc` 不单独成为候选，只随所属单元处理，连带删除按整个单元移除。

这条规则优先于“未显式选择删除时保留多余内容”：区域单元内部不会保留陈旧 `.mcc`。
