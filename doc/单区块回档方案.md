# 单区块回档方案

本文定义把快照中的单个区块写回世界时的处理范围，重点是 POI 的还原方式。整存档恢复见[离线回档设计方案](离线回档设计方案.md)与[快照到游戏存档](流程/快照到游戏存档.md)，不在本文范围内。

## 1. 范围

| 项 | 在线 | 离线 |
| --- | --- | --- |
| 入口 | `/foldbackup rollback chunk` | `foldbackup snapshot rollback` |
| 目标 | 已加载的区块 | 已停止运行的世界目录 |
| 地形、方块实体、实体 | 按快照写回，实体冲突时保留现状 | 按快照写回，实体冲突时保留现状 |
| POI | 按恢复后的方块重建，票据按范围内的已加载实体重算 | 完全按快照还原 |
| 区块外 | 不写 | 不写 |

两条路径的共同边界：

- 只写目标区块的 POI 记录，不修改区块外的记录。
- 玩家数据与世界级配置不在范围内。
- 目标区块在快照中不存在时终止，不产生任何写入。

## 2. 两条路径为什么不同

POI 记录由位置、类型和 `free_tickets` 三部分组成。位置与类型是方块状态，`free_tickets` 只能在游戏内解释：它表示该位置的票据还有多少剩余。

在线回档能读到回档后的世界：实体已经替换，POI 管理器可查询，因此票据可以按“当前谁持有”重算，结果与回档后的真实世界一致。

离线回档要拿到持票者，必须解析实体存档中的村民记忆，并把“哪些记忆占票、如何计数”的游戏规则搬进 `core`；而 `core` 层不引入 Minecraft 依赖。因此离线选择忠于快照：POI 列整体按快照写回。

## 3. 在线路径

### 3.1 执行顺序

```text
在线区块回档
├─ 解析快照与目标区块 NBT
├─ 实体预校验
├─ 反序列化快照区块
├─ 替换 section
├─ 替换方块实体
├─ 应用实体回档
├─ 重建 POI
└─ 修复光照并同步客户端
```

POI 重建排在实体回档之后：票据要按回档后的村民记忆计算。与回档其余步骤一样，重建在服务器主线程完成。

### 3.2 重建步骤

```text
重建目标区块 POI
├─ 移除目标区块内的全部现有记录
├─ 按恢复后的 section 重建记录
│  └─ 新记录的 free_tickets 等于该类型的 maxTickets
├─ 统计目标区块内每个位置的持票者数
└─ 按位置补占票据
```

### 3.3 扫描范围

| 项 | 值 | 说明 |
| --- | --- | --- |
| 半径 | 3 区块（±48 方块） | 覆盖原版村民寻找 POI 的半径 |
| 实体来源 | 范围内已加载的村民 | 不读取实体存档 |
| 写入位置 | 只写目标区块内的记录 | 区块外的记录一律不动 |

限制范围是为了避免为一次单区块回档遍历整个世界或读取实体存档。超出范围或所在区块未加载的持票者按未持票处理。

### 3.4 落地

重建只改内存中的 POI 记录。新增或占用票据会把所在列标记为脏，由下一次区块保存或周期写回 `poi/r.x.z.mca`，不直接写区域文件。

## 4. 离线路径

### 4.1 区域单元

`poi/r.x.z.mca` 与 `region/`、`entities/` 下的同名文件并列，作为第三个区域单元参与同一次暂存与替换：参与的单元先全部准备，再依次落地，任一失败按现有规则恢复已落地的文件。`.mcc` 随所属单元处理，规则与其他区域单元一致。目标区块没有需要写回的 POI 时，该单元不参与（见 4.2）。

### 4.2 列的内容

- 快照中有该列：把该列的区块 NBT 原样写入。
- 快照中没有该列，但目标存在 `poi/r.x.z.mca`：写入空列，不删除文件，表示“快照时刻该区块没有 POI”。
- 快照中没有该列，目标也没有 `poi/r.x.z.mca`：该单元不参与。

### 4.3 区块外

只替换目标区块所在的格，同一region文件中其余格的 NBT 原样转发。

## 5. 一致性边界

- 在线：超出扫描半径或所在区块未加载的村民不会被计入，其票据按空闲处理。这类 POI 可能被重复占用，但不会出现“记录存在、无持有者、永不可用”的永久占用。
- 在线：目标区块内被恢复的村民如果持有区块外的 POI，区块外的票据不会重算。此时区块外的票据可能与村民记忆不符，这是不写区块外换来的代价。
- 在线：只保证原版村民（`Villager`）的四个记忆参与重算。模组实体，或模组给村民添加的自定义记忆，持有的票据不在范围内；重建后这些票据按空闲处理，可能与实际持有者不一致。
- 在线：POI 以恢复后的方块为准，不读快照的 POI 数据。快照自身的 POI 与方块不一致时，在线会纠正，离线会保留。
